# Retail Store Management Database

## Project Overview

This project is a simulated retail store management database built with MySQL.

The database is designed to manage customers, employees, suppliers, products, inventory, orders, order details, payments, and product categories.

The project demonstrates database design and SQL skills, including:

- Relational database design
- 3NF normalization
- Primary and foreign keys
- SQL queries and business analysis
- Views
- Stored procedures
- Entity Relationship Diagram (ERD)

The goal of the project is to demonstrate how a structured relational database can be used to support everyday retail business operations and generate useful business insights.

---

## Database Structure

The database contains 9 related tables:

| Table | Purpose |
|---|---|
| Customers | Stores customer information |
| Employees | Stores employee information |
| Suppliers | Stores supplier information |
| Categories | Stores product categories |
| Products | Stores product information and pricing |
| Inventory | Tracks product stock levels and reorder levels |
| Orders | Stores customer orders and order status |
| OrderDetails | Stores the products and quantities included in each order |
| Payments | Stores payment information for orders |

The database uses primary keys and foreign keys to establish relationships between the tables and maintain data integrity.

## SQL Analysis

The project includes business-focused SQL queries designed to answer questions such as:

1. Which products are low in stock?
2. How many products are in each category?
3. Which customers have placed more than one order?
4. Which products have sold the most units?
5. How much revenue has the store generated from completed orders?
6. Which customers have spent the most money?
7. What is the average order value?
8. Which payment methods are used most often?
9. Which employee processed the most orders?
10. Which product category generates the most revenue?

These queries demonstrate the use of:

- SELECT
- JOIN
- WHERE
- GROUP BY
- HAVING
- ORDER BY
- Aggregate functions such as COUNT, SUM, and AVG
- Subqueries

---

## Views

The database includes three views for commonly used business analysis:

- `low_stock_products` — identifies products that have reached or fallen below their reorder level.
- `customer_spending` — shows how much each customer has spent on completed orders.
- `category_revenue` — shows revenue generated by each product category from completed orders.

Views provide a reusable way to access frequently used queries.

---

## Stored Procedures

The database includes three stored procedures:

- `get_low_stock_products()` — retrieves products with low stock.
- `get_customer_spending()` — retrieves customer spending on completed orders.
- `get_category_revenue()` — retrieves revenue by product category.

These procedures demonstrate how reusable SQL logic can be stored and executed within the database.
